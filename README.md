# 南科大羽毛球场预约助手

Windows 电脑版企业微信的界面操作脚本，面向「工作台 → 校园场馆/会议预约系统 → 场地预约 → 润杨羽毛球馆」。**项目处于试运行阶段，依赖特定界面布局，不保证预约成功。**

本项目与南方科技大学、场馆管理方及企业微信无隶属或授权关系。

## 实现方式与当前状态

- 使用 PowerShell、Windows 界面控件、鼠标键盘模拟及局部截图检查。
- 单进程顺序尝试，不调用场馆预约接口，不抓取网络请求，不使用多线程并发预约。
- 支持配置日期、时段、场地优先顺序、人数和手机号。
- 支持提前启动，等待当天指定开放时间；支持提交前停止的试运行模式。
- 正常无可用时段时，按配置顺序返回并尝试下一项；出现无法确认的页面状态时停止。
- 人机验证需要本人手动完成；没有自动识别、破解或绕过验证功能。

### 最近修复（2026-09-26）

1. 工作台入口：先判断侧边栏选中状态；只有确认仍在消息页时才允许再次点击，最多两次。移除了可能误认侧栏标签的文字查找。
2. 场馆入口：局部截图确认目标卡片，进入后核对前两张羽毛球缩略图，避免将协议遮罩淡出误判为页面跳转。取消入口失败后盲目下翻。
3. 日期选择：明天或后天先实际点击再确认；日期下划线改为逐像素行检测，避免漏掉一像素高的选中线。
4. 减少重复最大化及固定等待；部分入口按 40 毫秒间隔检查。该数值是检查间隔，不代表整个步骤耗时。

这些修复经过截图检查、部分模拟和配置/语法检查；最新日期修复尚未完成真实预约端到端验证。

## 运行条件

- Windows，安装电脑版企业微信，并由本人提前登录。
- Windows PowerShell 5.1（启动脚本使用系统自带的 `powershell.exe`）。
- 电脑保持解锁、联网且不休眠，运行期间不要操作鼠标、切换窗口或改变缩放。
- 当前视觉模板来自约 **2560×1600** 的屏幕截图；脚本会最大化窗口，但不等于支持任意分辨率、DPI、主题或浏览器缩放。换电脑或布局变化后需重新校准。

## 快速开始

1. 下载并解压完整项目，保留 `assets` 文件夹和 `visual-probe.cs`。
2. 打开并登录企业微信。
3. 双击 `run.cmd`。首次运行会从 `config.example.json` 创建本机 `config.json` 并打开记事本。
4. 修改 `config.json`，按 **Ctrl+S 保存**，再启动 `run.cmd`。
5. 首次使用保持 `dry_run: true`，确认日期、场号、时段和填写信息正确。正式提交需要改为 `false` 并重新启动。

**实际生效的是 `config.json`，不是 `config.example.json`。** 程序启动时读取配置；修改后必须重启程序。不要同时运行多份脚本。

## 配置示例

下面展示两个备选时段。它们是依次尝试的选择，不表示自动预约两场；成功后程序停止。

```json
{
  "date": "auto_third_day",
  "time_ranges": [
    {"start": "16:00", "end": "17:00"},
    {"start": "08:00", "end": "08:30"}
  ],
  "court_priority": [7, 2, 5, 1, 3],
  "priority_mode": "time_first",
  "people": 2,
  "phone": "请填写本人11位手机号",
  "release_time": "20:00:00",
  "max_navigation_resets": 2,
  "max_attempts": 20,
  "wait_for_release": true,
  "dry_run": true
}
```

| 字段 | 含义 |
| --- | --- |
| `date` | 目标日期，如 `2026-09-27`；`auto_third_day` 按执行时的系统日期加两天计算。跨午夜运行可能改变目标日期，固定计划建议填写明确日期。 |
| `time_ranges` | 按顺序尝试的时间段。必须写两位小时，如 `08:00`，不能写 `8:00`；结束晚于开始，分钟为 `00` 或 `30`，页面时间范围为 08:00–23:00。 |
| `court_priority` | 1–10 的不重复场号，可只填写部分，按顺序尝试。 |
| `priority_mode` | `time_first`：先遍历当前时段的所有场号；`court_first`：先遍历当前场号的所有时段。 |
| `people` | 实际使用人数，正整数。 |
| `phone` | 本人的 11 位手机号，使用英文双引号包裹。 |
| `release_time` | 等待的本地时间，格式 `HH:mm:ss`。 |
| `wait_for_release` | `true`：到达球场列表后等待当天开放时间；已过该时间则直接继续。`false`：立即尝试。 |
| `dry_run` | `true`：选时段、填写信息后，在提交前停止；`false`：核对表单后尝试点击预约。 |
| `max_attempts` | 最多尝试多少个“场号＋时段”组合。 |
| `max_navigation_resets` | 导航异常或预约被拒绝后最多允许的恢复次数；不代表能恢复所有异常。 |

JSON 中数字和 `true`/`false` 不加引号，不允许注释或末尾多余逗号。手机号为私人信息，不要提交或截图公开。

### 日期与晚上八点

当前代码按使用者提供的页面行为处理：20:00 前定位今天、明天两栏；20:00 后定位今天、明天、后天三栏，不操作“选择日期”。这是实现假设，须以实际页面及学校规则为准。

例如目标 `2026-09-27`：在 2026-09-25 运行对应后天，在 2026-09-26 运行对应明天。首次进入某个场号默认显示今天；目标为今天时沿用默认页。

`wait_for_release` **不会创建系统定时任务、自动启动电脑或程序**。需提前本人启动并保持程序运行。若只是查询已经开放的日期，可设为 `false`。

## 停止和排查

- 停止预约脚本：运行同目录 `stop-booking.cmd`，或在运行终端按 `Ctrl+C`。
- 企业微信仍无响应时：`stop-wecom.cmd` 会强制结束企业微信进程，可能丢失未保存内容；只在需要时使用。
- 查看 `booking.log` 最后几行。界面看似停住，可能是等待开放，也可能是脚本已经报错退出。
- `ParseExact` 报错：先检查时段是否写成 `08:00`、`08:30`，以及开放时间是否为 `20:00:00`。
- 日期已变色但停止：检查是否使用包含最新 `booking.ps1` 和 `visual-probe.cs` 的完整版本；不要混用旧文件。
- 未识别到工作台、入口或场馆：检查窗口最大化、缩放、前台焦点；可能需要重新校准模板。
- 提交状态不明：先手动查看“我的预约”，避免重复提交。出现人机验证请本人完成并核对结果。

仅检查本机配置、不操作预约界面：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\booking.ps1 -ValidateOnly
```

`-Inspect` 是界面控件诊断选项，会尝试打开预约页面，不是纯配置检查；部分内嵌页面控件扫描可能较慢。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `run.cmd` | 检查配置并启动脚本 |
| `booking.ps1` | 导航、日期/时段选择、表单及恢复逻辑 |
| `visual-probe.cs`、`assets/` | 局部截图采样、模板匹配和日期下划线检测 |
| `config.example.json` | 可公开的配置模板 |
| `config.json` | 本机实际配置，不入库 |
| `stop-booking.cmd`、`stop-booking.ps1` | 停止本目录的预约进程 |
| `stop-wecom.cmd` | 强制关闭企业微信 |

`.gitignore` 排除本机配置、日志、进程记录及压缩包。公开仓库只包含代码、说明、配置模板和裁剪后的界面识别素材；提交变更前仍应自行检查是否含个人信息。
